Juice: particles, shake, tweens and sound

2D track · lesson 6 of 6 · about 30 minutes

The same game can feel dead or alive. The difference is a dozen tiny reactions to every action.

1 The idea

"Juice" is feedback: when something happens, the game reacts in several ways at once. A brick breaking in Breakout plays a sound, shakes the screen a little, bursts into particles and adds to the score. None of that changes the rules, and all of it changes how the game feels.

Kindling has a tool for each: particles (tiny short-lived dots), camera shake, tweens (animate any number with an easing curve), timers, and sound effects generated from code. A classic extra is hit-stop: freeze the game for a few hundredths of a second on a big hit, so it lands with weight.

3 Walkthrough

  1. Breakout's brick hit, from samples/2d/03-breakout/main.js: four reactions in five lines. 
    brick.hits -= 1;
score += 10;
camera.shake(2, 0.1);
if (brick.hits <= 0) {
  particles.emit({ ...presets.explosion, count: 12, x: brick.x + brick.width / 2, y: brick.y + brick.height / 2 });
  playSfx(audio, "hit");
}
  2. Bricks do not just appear; each one grows in, one after another, with a tween and a timer: 
    game.timers.after((row * 11 + column) * 0.01, () => game.tweens.to(brick, { scale: 1 }, 0.4, easeOutBack));
  3. Sound effects are made from code: a wave whose pitch slides. Rising sounds happy, falling sounds like losing. Design your own in the sound visualization, which prints the line of code. 
    playSfx(audio, "coin");
playTone(audio, { type: "square", frequency: 220, frequencyEnd: 660, duration: 0.15, volume: 0.2 });
  4. Particles, shake and tweens update in the game step, so pausing the game pauses them. That is why they are owned by game (game.tweens, game.timers) or updated in your scene's update.

4 Exercise

Add hit-stop to Breakout: when a brick is destroyed, freeze the game (ball, paddle, particles) for 0.06 seconds. Then add a score pop: the score text briefly grows to 1.5 times its size and settles back.

Hint 1

Keep let freezeSeconds = 0. At the top of update: if it is above zero, subtract stepSeconds and return before anything moves.

Hint 2

For the pop: const scoreLook = { size: 8 }; on a hit, set scoreLook.size = 12 and tween it back with game.tweens.to(scoreLook, { size: 8 }, 0.25, easeOutCubic). Draw the score with size: scoreLook.size.

Solution

One way to do it (yours can be different and still right):

let freezeSeconds = 0;
const scoreLook = { size: 8 };

// First lines of update(game, stepSeconds):
if (freezeSeconds > 0) {
  freezeSeconds -= stepSeconds;
  return;                       // nothing moves while frozen
}

// Where a brick is destroyed (brick.hits <= 0):
freezeSeconds = 0.06;
scoreLook.size = 12;
game.tweens.to(scoreLook, { size: 8 }, 0.25, easeOutCubic);

// In render, where the score is drawn:
text(context, "SCORE " + score, 6, 6, { color: "#cccccc", size: Math.round(scoreLook.size) });

Import easeOutCubic from kindling/math/easing.js. Keep the freeze short: past about 0.1 seconds it starts to feel like lag instead of impact.
