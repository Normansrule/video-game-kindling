3D transforms: model, view, projection

3D track · lesson 1 of 4 · about 35 minutes

Every corner of every 3D object goes through three matrices on its way to your screen. Understand those three and 3D stops being magic.

1 The idea

A 3D model is a list of corners (vertices) around its own center. To draw it, each corner is multiplied by three 4×4 matrices:

  1. Model: where this object is in the world, how it is turned, how big it is.
  2. View: the world moved so the camera sits at the center, looking down -z. (The camera never moves; the world moves the opposite way.)
  3. Projection: the lens. Far things get smaller, and everything is squashed into the screen. The FOV (field of view) is how wide the lens sees.

Matrices combine by multiplying, and order matters: "turn, then move" spins an object in place somewhere else; "move, then turn" swings it around the center like a moon. In Kindling's code you read the steps from the last call back to the first.

3 Walkthrough

  1. The spinning cube sample builds a model matrix each frame. rotationY makes a fresh matrix; rotateX adds a step to it: 
    let model = mat4.rotationY(angle);
model = mat4.rotateX(model, angle * 0.6);
renderer.drawMesh(cubeMesh, model, { texture: crateTexture, color: [1, 1, 1] });
  2. Placing, turning and sizing an object, as the lit-scene sample does for every tree. Read it bottom to top: scale the tree, turn it, then move it to its spot. 
    let model = mat4.translation(tree.x, 0, tree.z);
model = mat4.rotateY(model, tree.turn);
model = mat4.scale(model, { x: tree.scale, y: tree.scale, z: tree.scale });
  3. The camera gives the other two matrices. lookAt builds the view from where the eye is and what it looks at; perspective builds the lens: 
    camera.view = () => mat4.lookAt(camera.position(), camera.target, { x: 0, y: 1, z: 0 });
camera.projection = (aspect) => mat4.perspective(camera.fieldOfView, aspect, camera.near, camera.far);
  4. On the GPU (graphics processing unit), the vertex shader in engine/3d/lighting.js does the multiplication for every corner, right to left: 
    vec4 world = u_model * vec4(a_position, 1.0);   // model: corner -> world
gl_Position = u_projection * u_view * world;     // then view, then projection

4 Exercise

In samples/3d/01-spinning-cube/main.js, add a small moon (a sphere of radius 0.25) that orbits the cube at a distance of 2, twice as fast as the cube spins.

Hint 1

Make the mesh once with createMesh(screen.gl, sphere(0.25, 12, 8)); import sphere from kindling/3d/primitives.js.

Hint 2

For an orbit you want "move out, then turn around the center". Written in code that is rotationY first, then translate.

Solution

One way to do it (yours can be different and still right):

import { cube, sphere } from "kindling/3d/primitives.js";
const moonMesh = createMesh(screen.gl, sphere(0.25, 12, 8));

// In render(), after drawing the cube:
let moon = mat4.rotationY(angle * 2);              // second: swing around the center
moon = mat4.translate(moon, { x: 2, y: 0, z: 0 }); // first: move 2 out along x
renderer.drawMesh(moonMesh, moon, { color: [0.8, 0.85, 1], shininess: 8 });

Swap the two lines (translation first, then rotateY) and the moon spins in place at x = 2 instead of orbiting. That is the order rule in action.
