Drawing and input

2D track · lesson 2 of 6 · about 25 minutes

Draw rectangles and text on a canvas, then make them respond to any input device through one table of actions.

1 The idea

A 2D game draws on a <canvas> with the browser's Canvas 2D API: rectangles, circles, images and text. Kindling games choose a small game size such as 320×180 and let the engine scale it up to fit the window. You always think in game pixels.

Input has three questions per step: is it held, was it pressed since the last step, was it released since the last step. Use held for running, pressed for jumping. And instead of asking about keys, games ask about actions: you name a control jump and list everything that triggers it (Space, W, gamepad A, a touch button). The rest of the code never mentions a key again.

2 See it

Hold and tap Space. Slow the steps down and tap fast: the tap still shows up as "pressed" even when it never shows as "held".

Open it in its own tab (easier on a phone).

3 Walkthrough

  1. Pong declares its actions once, in samples/2d/01-pong/main.js: 
    const game = createGame({
  width: 320, height: 180,
  actions: {
    up: ["ArrowUp", "KeyW", "pad:Up", "pad:LeftY-", "touch:up"],
    down: ["ArrowDown", "KeyS", "pad:Down", "pad:LeftY+", "touch:down"],
    start: ["Space", "Enter", "pad:A", "pad:Start", "mouse:0"],
  },
});
game.input.touch.addButton("up", 0, 0, 60, 90, "▲");     // the left side of the screen
game.input.touch.addButton("down", 0, 90, 60, 90, "▼");
  2. Moving the paddle uses axis, which turns two actions into -1, 0 or +1, and clamp keeps it on screen: 
    player.y += game.actions.axis("up", "down") * PADDLE_SPEED * stepSeconds;
player.y = clamp(player.y, 0, HEIGHT - PADDLE_HEIGHT);
  3. Drawing helpers live in kindling/2d/draw.js. The order you draw in is the order things stack: background first, HUD (heads-up display) last. 
    fillRect(context, player.x, player.y, player.width, player.height, "#4fa3ff");
text(context, String(player.score), 140, 8, { size: 16, align: "center", color: "#4fa3ff" });
  4. After every step the engine calls endStep() on each device, clearing pressed and released. That is the whole trick behind "pressed since the last step".

4 Exercise

Make a 12×12 square that moves in all four directions with arrow keys, WASD or a gamepad stick at 100 pixels per second. While the boost action (Shift or gamepad B) is held, it moves twice as fast. Each time paint (Space or gamepad A) is pressed, it changes to a random color.

Hint 1

Two axes: axis("left", "right") and axis("up", "down"). Shift is "ShiftLeft".

Hint 2

random.pick([...colors]) from kindling/math/random.js picks a color.

Solution

One way to do it (yours can be different and still right):

import { createGame } from "kindling/game.js";
import { fillRect } from "kindling/2d/draw.js";
import { random } from "kindling/math/random.js";

const game = createGame({
  width: 320, height: 180,
  actions: {
    left: ["ArrowLeft", "KeyA", "pad:LeftX-"], right: ["ArrowRight", "KeyD", "pad:LeftX+"],
    up: ["ArrowUp", "KeyW", "pad:LeftY-"], down: ["ArrowDown", "KeyS", "pad:LeftY+"],
    boost: ["ShiftLeft", "pad:B"], paint: ["Space", "pad:A"],
  },
});
const square = { x: 154, y: 84, color: "#ffb347" };

game.scenes.add("play", {
  update(game, stepSeconds) {
    const speed = game.actions.isDown("boost") ? 200 : 100;
    square.x += game.actions.axis("left", "right") * speed * stepSeconds;
    square.y += game.actions.axis("up", "down") * speed * stepSeconds;
    if (game.actions.wasPressed("paint")) square.color = random.pick(["#ffb347", "#4fa3ff", "#3fbf6a", "#e05a7a"]);
  },
  render(game, context) {
    fillRect(context, square.x, square.y, 12, 12, square.color);
  },
});
game.start("play");

Moving diagonally is faster than moving straight (about 1.41 times). Fixing that is a nice extra: put the two axes in a vector and use vec2.normalize when its length is over 1.
